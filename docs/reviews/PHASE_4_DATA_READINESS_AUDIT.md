## 1. Executive Summary

This audit resolves the fundamental data-accounting question posed in Section 2.4 of the Phase 4 Implementation Prompt:
> **Why does the corpus manifest report 12,522 normalized clause records, while the SQLite database and search indexes contain 9,454 indexed clauses?**

Through physical database inspection, schema analysis, and document-by-document parsing trace, this audit has established the exact root cause:
1. **The Database Primary Key Constraint:** In `RuleClauseEntity`, the primary key is `id = Column(String, primary_key=True)`, where `id` was generated by `ClauseParser` as `f"{document_id}:{clause_number}"`.
2. **Namespace Collisions in Extracted Source PDFs:**
   - **ICC Playing Conditions (7 documents):** Clauses inside Appendices (e.g. Appendix A *Definitions* Clause 1.1, Appendix C *Technology* Clause 1.1, Appendix D *DRS Protocols* Clause 1.1) share identical clause numbers (`1.1`, `1.2`, etc.) with the main body Playing Conditions. When inserted into the database, subsequent appendix clauses overwrote earlier main-body clauses.
   - **MCC Laws of Cricket (2026 Edition):** Pages 163–178 contain the *Index to the Laws*. Because the index entries use clause numbers (e.g. `1.1 Number of players 9`), the parser extracted them as clauses, causing index summary entries to overwrite the normative Law text from Page 9.
   - **MCC Laws of Cricket (2022 Edition):** This document is a bilingual Diglot (English & Hindi). The English text block and Hindi translation block were parsed sequentially under the same clause number, causing the Hindi text to overwrite the English text in the database.
   - **MCC Changes Explained (2026):** Multiple explanatory bullet points referenced the same amended clause number.

The sum of unique `id` values across all 11 documents is **exactly 9,454**, mathematically accounting for every single difference between the 12,522 extracted JSON items and the 9,454 database rows.

## 3. Impact Analysis on Retrieval and Answer Generation

### 3.1 Severity Assessment
- **High Severity (MCC Laws 2026):** Because the back index (pages 163–178) entries ran last, queries targeting MCC Laws (e.g. `MCC_LAWS_2026:1.1`) currently retrieve index page text (`1.1 Number of players 9`) rather than the operative Law text (`A match is played between two sides, each of eleven players, one of whom shall be captain...`).
- **High Severity (MCC Laws 2022):** The 2022 historical baseline currently holds Hindi translated text for several clauses rather than English text, impairing English keyword matching and semantic generation for historical queries.
- **Medium Severity (ICC Appendices vs Main Body):** In ICC Playing Conditions, where an Appendix has a clause `1.1` (e.g. DRS protocol Clause 1.1), the main Playing Condition clause `1.1` (Number of players) was overwritten. However, core playing conditions that do not collide (such as Clause `21.18` Free Hit, Clause `22.1` Wide, Clause `19.1` Boundaries) remained intact, which explains why Benchmark v1 achieved 100% exact accuracy on those tested clauses.

### 3.2 Explanatory vs. Normative Source Role
`MCC_CHANGES_EXPLAINED_2026` is an explanatory document issued by MCC to clarify the rationale of the 2026 4th Edition revisions.
- **Decision:** It must be classified with `scope_level = ScopeLevel.EXPLANATORY_REFERENCE` and `clause_type = ClauseType.EXPLANATORY`.
- **Constraint:** The Grounded Answer API must cite normative Laws (`MCC_LAWS_2026`) or official Playing Conditions (`ICC_*_2026`) as the authoritative basis for rulings, using the explanatory document strictly as contextual or illustrative evidence.

## 4. Remediation Architecture Plan

To ensure 100% data integrity, eliminate collisions, and restore all operative normative laws, definitions, and DRS protocols:

1. **Section-Aware Namespacing in `ClauseParser`:**
   - Detect document section transitions: `MAIN`, `APPENDIX_A` (Definitions), `APPENDIX_C` (Technology), `APPENDIX_D` (DRS), `APPENDIX_E` (Interrupted Matches/DLS).
   - Generate unique, deterministic IDs:
     - Main Playing Condition: `ICC_TEST_MEN_2026:1.1`
     - DRS Protocol: `ICC_TEST_MEN_2026:APP_D:1.1`
     - Appendix A Definition: `ICC_TEST_MEN_2026:APP_A:1.1`
2. **Exclude Back Index in `MCC_LAWS_2026`:**
   - Terminate extraction for `MCC_LAWS_2026` at Page 162 (end of Appendix E Wickets). Pages 163–178 (Index) are discarded from clause ingestion, preserving the authentic normative Laws 1 through 42.
3. **Filter English-Only in `MCC_LAWS_2022`:**
   - Parse only the English blocks of the 2022 Diglot edition, preserving the verbatim English text for all historical clauses.
4. **Automated Pipeline Execution:**
   - Re-extract clauses, regenerate 7 multi-view representations, rebuild `data/cricketiq.db`, update SQLite FTS5 index, and recompute dense embeddings.
   - Verify that all 67 existing tests and retrieval benchmarks continue to pass with 100% accuracy.
